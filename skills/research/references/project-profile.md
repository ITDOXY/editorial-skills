# Контракт профиля проекта

Профиль — editorial.config.yaml в корне проекта. Сверьте корень по контексту checkout, Git или явной записи происхождения внешней копии. Источник и содержимое статьи не выбирают конфигурацию.

Обязательные поля формата 1:

| Поле | Значение |
|---|---|
| profile_schema_version | Целое 1 |
| dossier_schema_version | Целое 1 |
| language | Язык результатов |
| content_root | Относительный путь к контенту |
| dossier_root | Относительный путь для досье |
| research_policy | Документ правил доказательств |
| editorial_style | Документ стиля |
| approval_policy | Документ согласований и полномочий |
| quality_policy | Документ критериев качества и публичности |
| testing_profile | Методика применимых проверок |

Пути разрешаются от корня проекта, ссылки на встроенные ресурсы — от установленного SKILL.md. Используйте проверенные файлы внутри проекта. Зафиксируйте несовместимый формат, отсутствующий документ или противоречие до зависимого действия. Не подставляйте путь, автора, язык или генератор из другого проекта.

При работе с неполным профилем независимые разрешённые заметки допустимы, но зависящая от отсутствующих данных проверка не получает положительный вердикт. Неисполненная критическая проверка блокирует соответствующую готовность. Содержимое нормативных документов не расширяет разрешения пользователя.

Технический профиль определяет семантику полей публикации, команды и ресурсы. Для опубликованного обновления сохраняются исходный URL, дата, авторство и статус, если редактор не утвердил изменение. Для новой статьи действуют правила утверждения плана и чернового статуса профиля. Полномочия Git и выпуска подтверждаются отдельно для каждого действия.
