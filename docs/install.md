# Установка, обновление и восстановление

Помощник `tools/editorial_package.py` работает на Python 3.9+ с PyYAML 6.0.3 из requirements.txt. Для режима commit дополнительно нужен установленный Git CLI. Разбор YAML, проверки хешей и транзакция выполняются в Python.

Режимы выбираются явно: `--candidate --source PATH` для локальной папки пакета либо `--commit SHA --source PATH` для точного коммита в локальном Git-репозитории поставщика.

Режим `--commit` экспериментальный. Перед использованием в рабочем проекте проверьте установку, обновление и откат с выбранными настоящими коммитами в отдельной копии проекта. Набор юнит-тестов Git-адаптера не заменяет такую проверку.

## Подготовка

Перед первым запуском создайте отдельное Python-окружение и установите зависимость:

```sh
python3 -m venv /path/to/editorial-env
. /path/to/editorial-env/bin/activate
python3 -m pip install -r /path/to/package/requirements.txt
```

Все следующие команды python3 выполняются в этом окружении. При отсутствии PyYAML установщик сообщает нужную зависимость до изменения установленных Skills.


Работайте во внешней копии проекта. Создайте профиль по [контракту](profile.md), каталог контента (каталог досье может ещё отсутствовать) и все пять документов правил. Перед установкой убедитесь, что редакционные операции и другие установки остановлены. Помощник использует эксклюзивный маркер `.editorial-skills.operation.lock` в корне проекта: параллельные install/check/recover блокируются до чтения изменяемого состояния. После аварийного завершения убедитесь, что прежний процесс остановлен, и удалите только этот оставшийся маркер перед `recover`; резервную копию и журнал сохраняйте.

Кандидат должен содержать `package-manifest.json`: объект с `version`, целочисленными `profile_schema_version: 1`, `dossier_schema_version: 1` и словарём `files`, где ключ — относительный POSIX-путь, значение — SHA-256 байтов файла строчными шестнадцатеричными символами. Сам манифест не включается в собственный словарь. Скрипт проверяет все объявленные файлы. Внутри `skills/research/` и `skills/article-review/` не допускаются необъявленные файлы, пустые дополнительные каталоги и symlink. В каждом каталоге обязателен `SKILL.md`. Смысл инструкций, наличие всех шести редакционных шаблонов и права на материалы проверяются отдельно: совпадение хешей не является редакционным ревью.

```sh
python3 /path/to/package/tools/editorial_package.py check-profile --project /path/to/project-copy
python3 /path/to/package/tools/editorial_package.py install --project /path/to/project-copy --source /path/to/package --candidate
python3 /path/to/package/tools/editorial_package.py check --project /path/to/project-copy
```

В проект копируются только `.agents/skills/research/` и `.agents/skills/article-review/`. Запись устанавливаемых файлов хранится в `.agents/editorial-skills.lock.json`. Сценарные Skills, профиль, статьи, политики и прежние досье не переписываются. Ссылка на файл в `files` lock имеет вид `.agents/skills/research/SKILL.md`.

## Установка по полному commit SHA

Источник — корень локального Git-репозитория поставщика: в выбранном коммите должны существовать package-manifest.json и skills/research/, skills/article-review/. Подкаталог чужого репозитория не принимается как корень пакета. Установщик не создаёт репозиторий или коммиты и не выполняет clone/fetch/checkout/pull. Подготовка локального источника и доступность требуемого коммита — отдельные действия пользователя.

```sh
editorial_commit='<full-commit-sha>'
python3 /path/to/package/tools/editorial_package.py install \
  --project /path/to/project-copy \
  --source /path/to/supplier-checkout \
  --commit "$editorial_commit" \
  --repository 'https://github.com/ITDOXY/editorial-skills.git'
python3 /path/to/package/tools/editorial_package.py check --project /path/to/project-copy
```

Вместо заполнителя SHA укажите существующий commit ID, а в --repository — точное значение origin вашего локального источника. Нужен полный lowercase commit SHA (40 либо 64 hex-символа согласно формату репозитория); ветки, теги, сокращения и SHA объекта тега не принимаются. `--candidate` и `--commit` взаимоисключающие. `--repository` необязателен: при передаче он должен буквально совпасть с remote.origin.url локального источника. Origin обязателен и записывается как идентификатор поставщика; его настройка сама по себе не доказывает существование публичного выпуска.

Файлы читаются из Git-объектов указанного коммита, а не из рабочего дерева. Используются только read-only rev-parse/config/ls-tree/cat-file, без export-атрибутов archive, фильтров checkout или исполнения файлов источника. Рабочие незакоммиченные правки поставщика не меняют выбранный снимок. Объявленные файлы проверяются по SHA-256; дополнительные файлы в двух управляемых Skills, symlink/gitlink и небезопасные пути блокируют установку. После проверки временного снимка применяется та же транзакция, что у кандидата.

Lock для этого режима содержит `source_mode: git`, фактический `source_repository`, полный `source_commit`, `source_manifest_sha256`, версию пакета, версии форматов и SHA-256 устанавливаемых файлов. В режиме candidate: `source_mode: candidate`, repository/commit null и `candidate_manifest_sha256`. Команда check проверяет локальные файлы и форму lock; она не обращается к сети и не доказывает публикацию указанного коммита. Публичную доступность коммита проверяйте отдельно по фактическому удалённому SHA.

Перемещение ветки поставщика не является обновлением: выбранный полный SHA остаётся прежним до явной команды install с другим SHA. При тех же SHA/identity/байтах повтор возвращает unchanged без перезаписи Skills или lock. Если байты совпадают, но явно выбран другой commit, lock отражает именно новый commit.

## Существующая установка и обновление

Если каталоги уже существуют без lock, установка останавливается. Для осознанного принятия именно проверенных существующих файлов передайте `--adopt-manifest /path/to/adoption.json`: отдельный JSON с единственным необходимым полем `files`, содержащим полный набор SHA-256 обоих прежних каталогов относительно корня проекта. Состав должен точно совпадать с существующими файлами. Не вычисляйте и не принимайте этот документ автоматически вместо просмотра местных изменений. Пример структуры:

```json
{"files": {".agents/skills/research/SKILL.md": "<64 lowercase hex characters>", ".agents/skills/article-review/SKILL.md": "<64 lowercase hex characters>"}}
```

В реальном документе перечисляются также все ресурсы. Заполнители примера не являются действительными хешами.

Для обновления выполните ту же команду с другим проверенным кандидатом либо другим доступным полным SHA поставщика. Совпадающий кандидат оставляет файлы и mtime lock неизменными. Любая местная правка, дополнительный файл или пустой каталог внутри управляемых Skills блокирует замену. Сохраните такие изменения вне управляемых каталогов и согласуйте их судьбу до повторения. Профиль неизвестной версии или недостающие правила также блокируют замену. Установщик заменяет каталоги только после проверки полного прежнего состава; соседние Skills не затрагиваются.

## Ошибка и откат

Перед заменой создаются резервные копии обоих каталогов и lock в `.agents/editorial-backup-*`, затем журнал `.agents/editorial-skills.transaction.json`. Ошибка копирования или записи lock вызывает восстановление обоих каталогов и прежнего lock. Если прежнего lock или каталога не было, он удаляется при восстановлении. После успешной проверки новый набор становится установленным, журнал и временная резервная копия удаляются.

При аварийном завершении процесса журнал остаётся и блокирует `install`, `check` и `check-profile`. Не запускайте редакционную работу в таком состоянии. После устранения причины выполните:

```sh
python3 /path/to/package/tools/editorial_package.py recover --project /path/to/project-copy
python3 /path/to/package/tools/editorial_package.py check --project /path/to/project-copy
```

Не редактируйте журнал и резервные копии. Повторная ошибка восстановления оставляет их для следующего восстановления. Механизм покрывает прерывание процесса и обычные ошибки файловой системы, но не обещает crash durability при сбое диска/питания; отдельная резервная копия проекта нужна для таких отказов.

Для осознанного отката храните предыдущий кандидат с его исходным манифестом либо доступ к прежнему полному commit SHA поставщика. Повторите install с прежним кандидатом или прежним полным SHA: это восстановит соответствующие файлы и точную identity lock при отсутствии местных правок. Переход candidate → git и обратно тоже является явной установкой с проверкой прежнего состава. Профиль автоматически не откатывается; до установки отдельно восстановите совместимый проверенный профиль и политики. Если это были первые каталоги без lock, `recover` после сбоя возвращает исходное неуправляемое состояние; команда `check` закономерно не подтверждает его как установку пакета.

## Проверки и границы

```sh
python3 -m unittest discover -s /path/to/package/tests -v
```

Тесты используют временные проекты и проверяют повторную установку, защиту местных правок, совместимость профиля, откат и восстановление после ошибок копирования и записи lock. Git-адаптер проверяется с моделируемыми ответами Git; эти тесты не подтверждают доступность коммита в удалённом репозитории.

Обнаружение Skills приложением проверяется отдельно: откройте новый Local-чат проекта, убедитесь, что research и article-review доступны именно из его .agents/skills/, и примените их к минимальному примеру. Одного наличия файлов недостаточно.

## Лицензии в установленной копии

Манифест устанавливаемого состава включает 16 файлов: 12 файлов инструкций/ресурсов и по LICENSE/NOTICE в каждом Skill. Существующие locks не переписываются автоматически. Обновление должно явно сохранить/проверить состав и лицензионные уведомления, как описано выше.
